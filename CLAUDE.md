Keep this simple. Before adding a component, dependency, abstraction or setting, check whether existing code already covers it.

UI: one clear primary action per screen. No taglines, decorative subtitles or redundant labels. If a screen only makes sense with explanatory text, rework the layout first. Keep text that does real work: errors, empty states, accessibility labels, and anything that prevents a user mistake.

When goals conflict, prioritize the end user, then code clarity, then convenience.

Code: descriptive names, small files with one job each, semantic HTML, so both people and coding agents can find things quickly.
